# CR-062: Local-Rewrite Harness (Deterministic-Minimal-LLM, Phase 1 of the local-LLM builder redesign)

## Metadata
- **Epic**: Local-LLM Drafting Pipeline (see `docs/reports/local-llm-builder-architecture-options.md`)
- **Status**: Implemented
- **Date**: 2026-07-10
- **Source**: 10-architecture design/judge workflow, re-run with a hard no-human-in-the-loop constraint after round 1 mistakenly ranked a checkpoint-based design first. This CR implements the #1-ranked design ("Deterministic-Minimal-LLM"), the first of a two-phase plan (phase 2, not started: layer in "Hybrid Anchor + Polish"'s claim-selection/cover-hook logic once this harness is proven at batch scale).

## Problem
The drafting pipeline calls zero local LLMs for generation by default (CR-059) — only `nomic-embed-text` for claim-selection embeddings. Every resume/cover-letter defect logged in `docs/reports/batch2-jd-tailoring-findings.md` therefore either ships as-is from deterministic templates or requires cloud-model manual polish. Jason asked for an investigation into decomposing generation into steps a small (2-14B) local Ollama model can reliably execute, to close some of that gap without cloud dependency, explicitly ruling out any design that requires a per-submission human step (the goal is saving time across batches of ~15-20 JDs, not adding a review queue).

## Decision
Implemented the narrowest possible LLM surface, deliberately smaller in scope than any of the other 9 candidate designs: one new call type ("sentence naturalization") that rephrases an already-selected, already-fact-checked piece of text, never chooses what to say.

- `scripts/local_rewrite.py` (new): `local_rewrite_sentence()` runs a 3-step escalation ladder — default model (`qwen2.5:7b-instruct-q4_K_M`) → same model retried once with the specific violated rule named → a different-family model (`phi3.5:3.8b-mini-instruct-q8_0`) as an independent second try → verbatim source text. Every attempt is schema-constrained (Ollama's native `format` param, already wired end-to-end in `utils.py`) and re-validated before acceptance. Two entry points: `local_rewrite_bullet()` (reuses the existing bullet gate stack — numeric grounding, blocked tools, seniority phrases, tone, verb-alignment, word cap) and `local_rewrite_prose()` (same checks minus the leading-verb requirement, for cover-letter paragraphs which aren't verb-first the way bullets are). Both add two checks beyond what exists today: numeric-token-set **equality** (not just no-new-fabrication — a rewrite can't silently drop a number either) and a proper-noun/tool subset check (every capitalized token in the output must already appear, case-insensitively, in the source).
- `scripts/llm_stages.py`: new `rewrite` stage, `STAGE_PROVIDERS["rewrite"] = ["local"]` (hard local-only, no cloud fallback — the whole point is proving local-only reliability). `call_llm_stage` now raises rather than silently substituting a cloud provider if a stage in `_HARD_PROVIDER_STAGES` has no configured provider, instead of falling through to `configured` like every other stage.
- Wired at 3 call sites, all gated behind a new additive `DRAFT_MODE=local_rewrite` value that never touches the `compose` default or the dormant `legacy_llm` path:
  1. `claim_composer.compose_bullet` — resume bullets.
  2. `local_draft_stages.build_summary_deterministic` — the one BM25-selected summary proof clause, after it's already passed the existing ranking/grounding checks.
  3. `cover_letter_renderer._render_block_letter` — each already-assembled cover-letter paragraph (hook, proof paragraphs, close), post-`blocks_to_prose`, pre word/char-limit trimming.
- **Real bug found and fixed during calibration, unrelated to the above but a direct consequence of introducing a new `DRAFT_MODE` value**: `pipeline_env.jd_profile_mode()` and `cover_hook_mode()` both defaulted to the free-form `"llm"` path for *any* `DRAFT_MODE` other than exactly `"compose"` — so `local_rewrite` was silently also switching JD profiling and cover-hook generation to ungrounded LLM behavior it was never meant to touch. Fixed by having both functions treat `local_rewrite` as compose-like.

## Acceptance Criteria
- `scripts/test_local_rewrite.py`: 26 tests, all passing — numeric/entity gate correctness (dropped number, fabricated number, invented tool, safe rewrite all correctly accepted/rejected), prose vs. bullet validator distinction, JSON extraction robustness, full escalation-ladder control flow with `call_llm_stage` monkeypatched (no network calls), audit logging.
- Full relevant suite (`test_local_rewrite.py`, `test_ai_signal_routing.py`, `test_cover_claim_picker.py`, `test_claim_preselection.py`, `test_summary_builder.py`): 61/62 passing. The one failure (`test_fintech_jd_prefers_dropoff_story`) is confirmed pre-existing via `git stash` — reproduces identically with none of this CR's changes applied.
- Live calibration run: tropic's archived JD run end-to-end through `draft_compiler.run()` in both `DRAFT_MODE=compose` (baseline) and `DRAFT_MODE=local_rewrite`, real Ollama calls, into scratch folders. After the `pipeline_env` fix, JD profiling and Core Competencies output were byte-identical between the two runs (isolating the diff to only the 3 wired call sites) and the rubric score was identical (76.2/100) to baseline — matching this design's own honest self-assessment ("same pass/fail rate, not a rubric-score gain, real gain is prose naturalness"). Both outputs passed `submission_linter` clean and compiled to exactly 1 page each.

## Out of Scope
- Claim selection, JD profiling, quota assignment, and section structure — untouched by design. Per the architecture's own ceiling estimate, this does not fix the structural/selection defects in `docs/reports/batch2-jd-tailoring-findings.md` (generic claim selection, duplicate cover-letter hooks, dropped sections) — only prose naturalness. Phase 2 (Hybrid Anchor + Polish) is the piece that addresses those, and should only be built after this harness's fallback rate is measured across a real 20-JD batch.
- `DRAFT_MODE=local_rewrite` is not yet the default — it's an opt-in flag for calibration. No decision has been made about when/whether to flip it.
- Company name and other cross-paragraph proper nouns in cover-letter rewrites are checked against that same paragraph's own prior text, not validated against a separate ground-truth source — acceptable since paragraphs are rewritten self-referentially (existing text in, rephrased text out), not generated from scratch.
