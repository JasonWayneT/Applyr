## The one thing to internalize before reading further

The authoring process is not a fixed spec anymore — it is a **living process with a self-repair protocol**. When a mistake surfaces (from Jason, from a reviewer, from a mechanical check), the fix goes into the actual mechanism (a script check, a Stage 0/1/2 step's wording, a ground-truth fact) — never a new narrative bullet appended to a growing list. The full protocol is in `.claude/skills/generate-submission/SKILL.md`'s own "Self-repair protocol" section. Follow it. It's the reason this file exists instead of a 20th accreted rule.

## Addendum — a second, deeper fidelity audit (same day, after the above)

Jason pointed out, fairly, that he'd explicitly asked for gap-finding multiple times today (a rubric-completeness pass, an adversarial design review, a project-wide staleness audit, the dry run, the 9-company batch) and none of them caught the specific class of bug a later fresh session found: the *documented* verification checklist had drifted out of sync with the actual scripts. Every one of today's earlier passes checked a different thing — design soundness, output quality, doc staleness — never "does this file's own text match what running it actually does." That is a real blind spot in self-review specifically: I was too close to my own work all day to catch it.

Response: ran a background agent with an explicit mandate to be adversarial toward the *process's own claims about itself*, not the output — pick one fresh, untouched archive JD, walk it through the current `SKILL.md` literally, and produce a PASS/FAIL/FINDING verdict for every single documented step, running every code sample as written (not a corrected version) and treating any drift between doc and reality as a finding. It used `colibri_group` (to exercise Stage 0's REJECT path — turned out to have a real `Closed` DB row) and `avetta` (to walk the full PASS path through Stage 3).

**Confirmed working correctly, not just claimed:** the Stage 0 database check (correctly rejected Colibri Group, correctly passed Avetta), the domain-anchoring check (found two real zero-anchor gaps in Avetta's JD neither of us had seen), the `.json`-not-`.md` requirement (reproduced the actual misclassification/false-block it warns about), the independent Stage 2 review operating on genuinely withheld context (caught a silently-dropped bridged gap, a repeated kicker-sentence template across all three cover-letter paragraphs — a device-repetition shape not previously named — and paraphrase-level restatement no mechanical check could catch), and Stage 3's PDF/page-count/manifest mechanics.

**Real bugs found and fixed:**
1. `quality_checker.check_resume`'s docstring claimed `(False, msg)` on failure; it actually raises `SelfCorrectionError` uncaught. Fixed the docstring and the documented command samples in `CLAUDE.md`/`AGENTS.md` (wrapped in `try/except`), left the function's actual raise-based contract alone since changing it would ripple into the still-live deterministic pipeline's other callers (`draft_compiler.py`, `verification_chain.py`, etc.) — a bigger, riskier change than the bug warranted.
2. `approved_metrics.py`'s allowlist still had `"6+"/"6 years"` (ground truth was corrected to 7 on 2026-07-18) and `"$800,000"/"$800K"` (the disabled ACC-114 claim) — meaning a rephrased version of either superseded/quarantined figure would sail through this check silently. First fix attempt (just deleting the entries) turned out to be a no-op: `_approved_match`'s substring-containment logic meant the standalone `"0"` entry already matched as a substring of any number containing a zero, and the extraction regex never even captures bare 1-2 digit numbers like "6" in the first place (a deliberate design choice to avoid false positives on small unrelated counts). Real fix: switched `_approved_match` to exact digit-sequence comparison instead of substring containment (closes the accidental-wildcard hole without losing any legitimate fuzzy match), widened `submission_linter.py`'s `LR-012` to catch `$800K`/`$800,000` without requiring the word "Canadian" adjacent, and added a new `LR-013` specifically for the superseded years figure (the right layer for this, since the generic metrics sweep structurally can't catch small numbers by design). Found the test suite's own "clean" resume fixture had hardcoded "6 years" too — fixed that as well.
3. Two diverged copies of `BLOCKED_TOOLS` (`drafting_engine.py`, already fixed 2026-07-18 to unblock Pendo, and `local_draft_stages.py`, still blocking it) — literally the self-repair protocol's own cited "already fixed" example, recurring live in a sibling file. Synced.
4. `SKILL.md`'s own tail-end "Required Verification" line was missing the `approved_metrics` sweep even though Stage 2's code sample earlier in the *same file* correctly includes it — the identical documentation-drift defect, found a second time inside one document. Fixed.
5. `LR-009`'s "driven" buzzword block caught hyphenated compounds ("data-driven," "AI-driven") via word-boundary matching past the hyphen. Jason's call: exempt all hyphenated compounds, keep standalone "driven" blocked. Fixed with a negative lookbehind, verified both directions.

**Checked and confirmed NOT a bug** (worth recording so it isn't re-flagged later): `candidate_preferences.json`'s two blocked-title arrays (`blocked_titles`, `blocked_role_titles`) looked like config drift but are an intentional, working legacy-fallback pattern in `seniority_gate.py`'s `blocked_title_lists()` — the newer field takes precedence whenever present, and it is present and populated in the live file. No action needed.

**Still genuinely open, not fixed, needs deliberate testing rather than assumption:** Stage 0 step 4 (ambiguous blocked-industry fallback) and Stage 1 step 8 (early/Series-B stage-signal framing) were never exercised by either archive JD used across all of today's testing — not confirmed broken, just never actually triggered by real data yet.

**The meta-lesson, stated plainly for whoever reads this next:** verifying "does the design make sense" and verifying "does the documentation match what the code actually does right now" are different exercises. Today needed both, found gaps only in the second one, and self-review consistently missed it — it took a fresh, adversarial, execution-literal pass each time. If this process needs auditing again, don't just re-read the docs and reason about them; run them.
