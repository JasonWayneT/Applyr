# SESSION HANDOFF — 2026-09-03 — Resume header placeholder bug

**Status:** Found, not fixed. Jason is doing a broader review of `data/submissions/` (a number of folders are expected to be removed) and wants this folded into that broader cleanup rather than patched in isolation right now.

## What happened

`scripts/apply_resume_header.py` exists to deterministically inject Jason's real name/phone/email/LinkedIn/location into a freshly-authored `Resume.md`/`CoverLetter.md`, because the CR-074 closed-world authoring packet has no contact-info field and a compose agent correctly can't invent that PII (see the script's own header comment for the full rationale).

Its placeholder-detection regexes (`_PLACEHOLDER_LINE1`, `_PLACEHOLDER_LINE2`) only match a header where **both** the name line and the contact line are *fully* bracketed placeholders — e.g. `# [Name]` / `[Location] | [Phone] | [Email] | [LinkedIn]`. The comment at line 46 states this assumption explicitly: *"both lines are only ever fully bracketed placeholders in this failure mode, never partially real."*

That assumption is false. In practice, compose runs have produced a **mixed** header: real name and real location filled in (things a model can plausibly infer/know), but phone/email/LinkedIn left as literal `[phone]` / `[email]` / `[LinkedIn]` brackets (things it genuinely has no access to). Because line 1 (`# Jason Taylor`) doesn't match `_PLACEHOLDER_LINE1`, the script's header-patch branch never fires — it reports `"skipped (no placeholder found)"` and leaves the literal brackets in place, including in the **compiled PDF**.

Confirmed via `pypdf` extraction on `data/submissions/cariloop/Resume.pdf`:
```
Jason Taylor
San Diego, CA | [phone] | [email] | [LinkedIn]
```

## Fix needed

`apply_resume_header.py`'s placeholder detection needs to handle a **partial** placeholder line, not just the fully-bracketed case:
- Line 1 may already be the real name — don't require it to match `[Name]` before checking line 2.
- Line 2 may mix real segments (location) with bracketed segments (phone/email/LinkedIn) in any combination — substitute only the bracketed segments, per-field, rather than requiring the whole line to be a placeholder before touching it.
- `tenth_revolution_group`'s blank-line case needs its own handling (there's no placeholder to pattern-match against at all — the header line is simply missing).

After the regex/logic fix: re-run `apply_resume_header.py` against every surviving affected folder, then `scripts/compile_single.py` to recompile each `Resume.pdf`/`CoverLetter.pdf`, then spot-check the compiled PDF text (not just the `.md`) the way this session did, since the `.md` and `.pdf` can silently diverge if only one gets patched.
